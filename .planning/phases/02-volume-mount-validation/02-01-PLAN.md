**Create `entrypoint.sh`** in the project root:

```sh
#!/bin/sh
set -e

echo "==> LogBoost Web startup validation"

# HARD FAIL: /data must be writable — container cannot function without it
# Per user's locked decision: fail to start if main data directory not writable
if [ ! -w /data ]; then
    echo "ERROR: /data is not writable by container user (UID 1000)."
    echo "Fix on host: sudo chown -R 1000:1000 /opt/logboost"
    exit 1
fi
echo "  [OK] /data is writable"

# WARN ONLY: Binary is optional on startup — app handles missing binary gracefully
if [ ! -f "${LOGBOOST_PATH:-/usr/local/bin/logboost}" ]; then
    echo "  [WARN] LogBoost binary not found at ${LOGBOOST_PATH:-/usr/local/bin/logboost}"
    echo "         /health will report logboost_available: false"
fi

# WARN ONLY: MaxMind databases are optional — app downloads them
MAXMIND_CHECK="${MAXMIND_DIR:-/data/maxmind}"
if [ ! -d "$MAXMIND_CHECK" ] || [ -z "$(ls -A "$MAXMIND_CHECK" 2>/dev/null)" ]; then
    echo "  [WARN] MaxMind databases not found in $MAXMIND_CHECK"
    echo "         GeoIP enrichment will not work until .mmdb files are present"
fi

echo "==> Starting gunicorn"

# exec replaces shell process — gunicorn becomes PID 1 for proper signal handling
exec "$@"
```

Key requirements:
- Use `/bin/sh` NOT `/bin/bash` (bash is not in python:3.12-slim)
- Script MUST end with `exec "$@"` so gunicorn becomes PID 1 and receives SIGTERM
- Only HARD FAIL is /data not writable (user's locked decision)
- Binary and MaxMind missing produce warnings only (user's locked decision)

  <name>Task 2: Create docker-compose.yml and update .env.example</name>

**Create `docker-compose.yml`** in the project root:

```yaml
services:
  logboost-web:
    build: .
    env_file: .env
    environment:
      # Override Dockerfile defaults to use mounted data directories
      LOGBOOST_PATH: /usr/local/bin/logboost
      MAXMIND_DIR: /data/maxmind
      THREAT_DB_DIR: /data/intel
      LOGBOOST_DB_PATH: /data/db/logboost_admin.db
    ports:
      - "${LOGBOOST_PORT:-5000}:5000"
    volumes:
      # All mounts are read-write (user's locked decision — app updates these at runtime)
      # Binary (rw — app downloads/updates at runtime)
      - /opt/logboost/logboost:/usr/local/bin/logboost
      # MaxMind GeoIP databases (rw — app downloads/updates them)
      - /opt/logboost/maxmind:/data/maxmind
      # Threat intelligence (rw — binary creates threats.db)
      - /opt/logboost/intel:/data/intel
      # Cache files (rw — binary reads/writes dns.cache, idb.cache, whois.cache)
      - /opt/logboost/cache:/data/cache
      # Config files (rw — feed_config.json, mm_api.txt)
      - /opt/logboost/config:/data/config
      # Admin SQLite database (rw — persistent across rebuilds)
      - /opt/logboost/db:/data/db
      # Session uploads (rw — persistent, hardcoded to /app/uploads in app.py)
      - /opt/logboost/uploads:/app/uploads
      # Session output (rw — persistent, hardcoded to /app/output in app.py)
      - /opt/logboost/output:/app/output
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5000/health"]
      interval: 30s
      timeout: 10s
      start_period: 30s
      retries: 3
```

Key points:
- No `version:` field (deprecated in Compose v2)
- `build: .` so operator can build locally (not `image:` — we don't have a registry yet)
- `env_file: .env` loads operator secrets/config
- `environment:` overrides Dockerfile ENV defaults with mount-aligned paths
- LOGBOOST_DB_PATH MUST be `/data/db/logboost_admin.db` (NOT the Dockerfile default `/app/logboost_admin.db`) — this is critical for admin DB persistence
- All 8 volume mounts, NO `:ro` flags (user's locked decision: all read-write)
- uploads mounts to `/app/uploads` and output to `/app/output` (hardcoded in app.py, NOT env-var driven)
- Port uses env var with default: `${LOGBOOST_PORT:-5000}:5000`
- healthcheck matches existing Dockerfile HEALTHCHECK
