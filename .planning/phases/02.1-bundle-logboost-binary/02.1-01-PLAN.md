<task type="auto">
  <name>Task 1: Bundle LogBoost binary in Dockerfile and add /data/bin</name>
  <files>Dockerfile</files>
  <action>
Modify the Dockerfile to download and install the LogBoost Linux binary during the Docker build. All changes go BEFORE the `USER logboost` line (root is required for /usr/local/bin writes).

**Binary download RUN layer** -- Insert AFTER the `useradd` line (line 26) but BEFORE `WORKDIR /app` (line 29). Add an ARG and a single RUN that:

1. Add `ARG LOGBOOST_VERSION=prod_1_5_0` before the RUN (per user's locked decision to pin to `prod_1_5_0`)
2. `apt-get update && apt-get install -y --no-install-recommends unzip` (not in python:3.12-slim)
3. `curl -fsSL "https://github.com/joeavanzato/LogBoost/releases/download/${LOGBOOST_VERSION}/logboost_linux_amd64.zip" -o /tmp/logboost.zip`
4. `unzip /tmp/logboost.zip -d /tmp/logboost_extracted`
5. `find /tmp/logboost_extracted -type f \( -name "logboost" -o -name "LogBoost" \) -exec install -m 0755 {} /usr/local/bin/logboost \;` (handles both possible binary names)
6. `rm -rf /tmp/logboost.zip /tmp/logboost_extracted`
7. `apt-get purge -y --auto-remove unzip && rm -rf /var/lib/apt/lists/*`

All in a SINGLE RUN layer to keep the image clean (same pattern as build-essential purge).

**Build verification** -- Add a separate `RUN test -f /usr/local/bin/logboost && test -x /usr/local/bin/logboost` immediately after the download RUN. This causes the build to fail loudly if the binary wasn't installed correctly.

**Add /data/bin to mkdir** -- Update the existing `mkdir -p /data/maxmind /data/intel /data/cache /data/config /data/db` line (around line 60) to include `/data/bin`:
```
RUN mkdir -p /data/maxmind /data/intel /data/cache /data/config /data/db /data/bin \
    && chown -R logboost:logboost /data
```

This is where runtime-updated binaries will be stored (container user UID 1000 can write to /data/bin but NOT to /usr/local/bin/).

**Do NOT:**
- Use `ADD` with URL (Docker recommends curl + RUN instead)
- Put the download after `USER logboost` (will get permission denied on /usr/local/bin)
- Merge the download into the existing build-essential RUN layer (keep concerns separate for cache efficiency)
  </action>
  <verify>
Run `docker build -t logboost-web:test .` from the project root. The build must:
1. Complete without error

Expected: binary exists at `/usr/local/bin/logboost` with execute permission, `/data/bin/` exists and is empty, whoami returns `logboost`.
  </verify>
