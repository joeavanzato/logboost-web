## Decisions Made
- `get_effective_logboost_path()` called at request time, not import time: DB is not ready at module load in init_admin, so checking settings at call time avoids a startup crash
- `install_logboost_update` exempted via `csrf.exempt()` in `init_admin()` rather than a global `_csrf` pattern: cleaner, avoids polluting module namespace
- `threat_intel()` guard for "LogBoost path not configured" removed entirely: Docker mode always has the binary, the guard was non-Docker-only logic
- `get_feed_config_path()` simplified to a single-line constant return: no DB lookup needed, Docker volume path is fixed
- `LOGBOOST_BINARY` module global kept and updated in `install_logboost_update` and `init_admin` for any remaining internal callers within admin.py
